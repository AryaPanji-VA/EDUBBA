# Phase 14B — Propositions and Connectives: Discrete Mathematics Golden Lesson

One complete Discrete Mathematics vertical slice. The existing ROBIN learning
engine now teaches a non-programming course: shared infrastructure
understands multiple courses, Programming behavior is untouched, and the
learner can navigate to and learn Propositions and Connectives through the
same activities, deterministic grading, Smart Feedback, Robin Check, mastery,
progress, Source Mode, and Learning Log architecture.

## Manual database step (required)

The lesson structure and sources are NOT in the live database yet. Run these
two files manually in the Supabase SQL Editor, in order:

1. `database/phase14b-propositions-structure.sql` — adds the
   `logic-foundations` module and the `propositions` lesson under
   `discrete-math`. This file was generated by the Phase 13.3 ingestion
   mechanism (`generateCurriculumApplySql`), diffed against the pre-14B
   state; it is ADD-only and idempotent (`ON CONFLICT DO NOTHING`). Until it
   runs, `/api/courses/discrete-math` and `/api/lessons/propositions`
   return honest 404s naming this file, and the course/lesson pages show the
   same clear error.
2. `database/phase14b-propositions-sources.sql` — attaches two real,
   free textbook sources (Book of Proof; forall x: Calgary) to the lesson,
   following the phase12-operators-sources pattern. Optional at runtime: the
   lesson API tolerates an empty source list.

Sources support ROBIN's lesson content; they do NOT make the lesson
official. Nothing modifies live Supabase automatically.

## Cross-course generalization (Part A)

- **Trusted course resolution.** `LessonDefinition` now carries
  `courseSlug` (`lib/lessons/registry.ts`). The flat registry is keyed by
  lesson slug, which is therefore globally unique across courses — the
  constraint is documented on the type. All six Programming lessons declare
  `courseSlug: "programming"`; propositions declares `"discrete-math"`.
- **Progress API.** `GET /api/learning/progress?lesson=` loads progress with
  `definition.courseSlug`; `POST` accepts a client `courseSlug` only when it
  **equals** the registry's — client input can never override course
  ownership. No hardcoded course strings remain (verified by tests).
- **Robin chat Learning Log.** `logPreview.courseSlug` now comes from
  `definition.courseSlug`: Programming chats log `programming`, Propositions
  chats log `discrete-math`.
- **Shared renderer.** The activity code-block label is now copy-driven
  (`copy.codeLabel ?? "python"`) so Programming keeps "python" unchanged and
  the math lesson labels its blocks "notation". The practice-input label
  (`copy.oneLine`) and diagram label are lesson-localizable as before.
- **Course overview loader.** `lib/courses/overview.ts` extracts the
  course→modules→lessons queries, parameterized by slug. Both
  `/api/courses/programming` (refactored, identical response and messages)
  and `/api/courses/discrete-math` (new) use it. Course-specific setup
  messages stay in each route.
- **Navigation.** `/courses` cards deep-link through
  `courseOverviewRouteBySlug` (data-driven; programming and discrete-math
  only). `implementedDiscreteMathLessonSlugs` was added alongside the
  programming list.

## Lesson scope and flow (Part C)

Concepts: proposition, truth value, negation (¬), conjunction (∧),
disjunction (∨). No implication, biconditional, quantifiers, sets, proofs,
or De Morgan — the CONNECT stage previews them only.

15 activities using only existing primitives:

```
WHY (intro) → INTUITION (explain) → REPRESENT (example)
→ PREDICT identify-proposition (predict)
→ PREDICT false-is-still-proposition (predict)
→ SEE ¬ table (example) → TRY ¬p (practice, free text)
→ SEE ∧ table (example) → PREDICT p∧q (predict)
→ SEE ∨ table (example) → PREDICT p∨q both-true (predict)
→ TRY p∨q (practice, free text)
→ FORMALIZE → ROBIN CHECK → CONNECT
```

## Deterministic grading, misconceptions, Smart Feedback

- Predict activities: exact-match options with per-answer misconceptions.
- Practice activities: lesson-owned `checkAnswer` accepting normalized
  answers (true/false/benar/salah, case-insensitive, trimmed).
- Misconception taxonomy (all used, closed set):
  `command_is_proposition`, `question_is_proposition`,
  `proposition_requires_true`, `and_requires_one_true`, `or_is_exclusive`.
- Smart Feedback (AI) only explains after `gradeActivity` decides
  correctness; it can never re-grade. `and_confused_with_or` exists only in
  the Robin Check vocabulary, where it is relevant.

## Robin Check

Explain-back: "Kalau p bernilai true dan q bernilai false, jelasin dengan
kata-kata lu sendiri kenapa p ∧ q bernilai false." Rubric
(`propositions-check-instructions.ts`) evaluates conceptual understanding
of conjunction (concepts: proposition, truth_value, conjunction), accepts
beginner phrasing ("karena AND butuh dua-duanya true" is strong), judges
meaning not wording, and uses the existing strong/developing/shaky schema
and reinforcement prompts.

## Mastery

Five concepts (proposition, truth_value, negation, conjunction,
disjunction), lesson-owned `LessonMasteryConfig`; every concept has at least
one evidence source; Robin Check signal → evidence per the existing engine.
AI never sets mastery state.

## Source Mode

The full lesson works without AI: academic definitions, notation code
examples (all three truth tables), deterministic activities, quick checks,
and sources. Robin Check follows the existing graceful "continue without
AI" behavior. Notation is plain Unicode (¬ ∧ ∨) — no LaTeX/KaTeX.

## Known limitations

- The lesson depends on the two manual SQL files above until they are run.
- `useCurrentLesson`'s static fallback still points at Programming
  (acceptable per the 14A audit; persisted progress is multi-course).
- The Discrete Math course card on `/courses` still shows the pre-existing
  presentation-fallback `16%` (Phase 13.2 scope); the course page itself
  shows only real progress.
- Keyword-based `chatConcepts` heuristics (e.g. English "and") can
  over-trigger, same as existing lessons.
- No Guided Practice / Thinking / Sandbox content for math yet — deliberate;
  those are Programming-only tools until a phase adds math-appropriate
  practice.
